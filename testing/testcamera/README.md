# Perigee Camera Lab

A small Android-only Expo SDK 54 test app for Perigee's native camera and gallery requirements. It builds entirely on this computer—EAS Build and Expo Go are not involved. VisionCamera 5 supplies the native processed-photo pipeline; Expo supplies the application runtime and system integrations.

## Tested functions

- Native CameraX preview, front/back switching, tap-to-focus, flash, zoom, exposure, HDR, low-light, and distortion correction when hardware reports support
- Highest advertised 4:3 JPEG capture with quality prioritization
- Original image import through Android Photo Picker, without editing or recompression
- Save to Android MediaStore and open the native share sheet
- Photo dimensions, megapixels, file bytes, capture latency, capability checks, and an exportable JSON report

An emulator proves app integration, not camera quality. Use the matched procedure in [docs/physical-device-checklist.md](docs/physical-device-checklist.md) to compare this app with Google Camera on a physical Pixel.

## Verified local setup

- Node.js 22.19.0 and pnpm 10.28.0
- Oracle JDK 17.0.12 at `C:\Program Files\Java\jdk-17`
- Android SDK at `E:\Android\Sdk`
- Gradle 8.14.3, compile/target SDK 36, build tools 36.0.0, NDK 27.1.12297006
- Pixel 7 API 35 AVD, x86_64

`android/local.properties` is intentionally ignored. On this machine it contains:

```properties
sdk.dir=E:\\Android\\Sdk
```

## Build the standalone release locally

Run from this directory:

```powershell
pnpm install
pnpm typecheck
pnpm test
pnpm prebuild
$env:NODE_ENV = 'production'
pnpm build:release
```

Use `pnpm exec expo prebuild --platform android --clean --no-install` only when native files must be regenerated. A clean prebuild also removes `android/local.properties`, so restore the SDK line above afterward.

The release build produces two small standalone APKs:

- `android/app/build/outputs/apk/release/app-arm64-v8a-release.apk` — physical Pixel/modern Android phone
- `android/app/build/outputs/apk/release/app-x86_64-release.apk` — Pixel 7 Android Studio emulator

Start the installed Pixel 7 emulator and install its APK:

```powershell
Start-Process E:\Android\Sdk\emulator\emulator.exe -ArgumentList '-avd','Pixel_7_API_35','-no-snapshot-save','-gpu','auto'
E:\Android\Sdk\platform-tools\adb.exe wait-for-device
E:\Android\Sdk\platform-tools\adb.exe install -r android\app\build\outputs\apk\release\app-x86_64-release.apk
E:\Android\Sdk\platform-tools\adb.exe shell am start -n com.perigee.testcamera/.MainActivity
```

The release APK embeds `assets/index.android.bundle` and runs without Metro. The screenshot error came from installing a debug APK without Metro. If a debug build is intentionally used, run `pnpm start` and `adb reverse tcp:8081 tcp:8081` first.

## Size controls

The generated release uses R8 code minification, Android resource shrinking/optimization, compressed JavaScript, legacy native-library packaging, JPEG-only Expo decoders, and ABI splits. Only arm64 phone and x86_64 emulator binaries are emitted; there is no oversized universal APK.

`plugins/withAndroidReleaseOptimizations.js` owns these generated-native settings and also applies the React Native 0.81 RawProps compatibility flag needed by VisionCamera 5. Re-run Prebuild after changing native configuration.

## Scope and boundaries

- Expo does not require EAS: Prebuild plus the generated Gradle wrapper builds locally.
- No Expo-specific camera, picker, save, or sharing blocker was found in the tested path.
- A third-party camera can request high-quality processed output, but Android does not guarantee access to every proprietary multi-frame enhancement used by the stock Google Camera app.
- Unsupported device capabilities are shown as N/A, not failures.
- VisionCamera 5 does not expose a complete EXIF map through this capture result, so EXIF readback is reported as unavailable.
- These local release APKs use the generated debug signing key for testing. Configure a protected production signing key before distribution.

Expo Doctor's app-config sync check is disabled because `android` is generated by Prebuild. `react-native-nitro-image` is excluded only from its React Native Directory metadata check; the native release build and emulator run provide the integration evidence here.
